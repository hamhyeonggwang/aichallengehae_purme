# 보강 브릿지 (Bogang Bridge)

**치료 재배정 보조 시스템**

## 혹시 지금 자리 있나요

보호자가 가장 많이 하는 질문입니다. 치료가 취소되면 그 시간은 비고, 같은 시간에 그 치료를
기다리는 아동이 있습니다. 현장에서는 이 연결을 '보강'이라 부릅니다. 후보를 찾는 일은
자동으로, 배정은 담당자가 결정합니다.

이 저장소는 **AI 챌린지 해 예선 제출용 시연 프로토타입**입니다.

> 표시되는 아동·치료사·일정은 전부 가상 데이터입니다. 실제 진료 정보는 포함되어 있지 않습니다.

---

## 무엇을 하는가

| 단계 | 하는 일 | 담당 |
|---|---|---|
| 1 | 보호자 결석 문자 입력 | 사람 |
| 2 | 문자에서 아동·날짜·결석 범위·종목 추출 | **AI** |
| 3 | 빈 슬롯 계산 → 대기 명단 대조 → 후보 순위 | **규칙** |
| 4 | 치료사용 안내문 생성 | **AI** |
| 5 | 최종 배정 확정 | 사람 |

AI에게 "누가 먼저 치료받는가"를 결정하게 하지 않습니다.
언어를 다루는 일만 AI가 하고, 배정은 결정론적 규칙으로 계산합니다.

## 두 가지 실행 경로

| | 웹 프로토타입 (`app/`) | n8n 워크플로우 (`n8n/`) |
|---|---|---|
| 목적 | 심사·시연용 | 기관 내부 실제 실행 |
| 위치 | Vercel 공개 웹 | 기관 내부망 |
| 추출 | Claude API (서버 프록시) | Ollama 로컬 |
| 데이터 | 가상 데이터 | 기관 CSV |

**매칭 규칙은 두 경로가 동일합니다.** 웹에서 확인한 결과가 현장에서도 같게 나옵니다.
자세한 내용은 [`n8n/README.md`](./n8n/README.md)를 참고하십시오.

## 실행

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 입력
npm run dev
```

API 키가 없어도 동작합니다. 이 경우 `lib/fallbackParser.ts`의 정규식 파서로 자동 전환되며,
화면에 "규칙 파서로 처리됨"이 표시됩니다.

### 배포 (Vercel)

1. GitHub 저장소 연결
2. 환경변수 등록
   - `ANTHROPIC_API_KEY` — **서버 전용.** 클라이언트 번들에 포함되지 않습니다
   - `ANTHROPIC_MODEL` — 사용 가능한 모델 ID로 조정
3. 배포 후 **시크릿 창**에서 접속 확인 (로그인 벽이 없어야 합니다)

## 다른 기관에서 쓰려면

핵심은 `lib/csv.ts` 하나입니다. 시스템을 바꾸지 않고, 대기 명단을 아래 형식의 CSV로 내보내기만 하면 됩니다.

```csv
child_id,alias,admission_type,therapy,remaining,waiting_days,busy_times
C-01,아동 가,입원,HYDRO,1,19,10:00|14:00
```

| 열 | 의미 |
|---|---|
| `child_id` | 내부 식별자 (실명 금지) |
| `alias` | 화면 표시용 별칭 |
| `admission_type` | `입원` 또는 `낮병동` |
| `therapy` | 치료 종목 코드 (`lib/mockData.ts`의 `THERAPIES` 참조) |
| `remaining` | **잔여 기회** — 서비스를 받을 수 있는 남은 횟수 |
| `waiting_days` | 대기 경과일 |
| `busy_times` | 당일 이미 잡힌 시각, `\|`로 구분 |

### 도메인 번역

이 도구의 개념은 의료에 종속되지 않습니다.

| 이 저장소 | 재활병원 | 복지관 | 방문요양 | 상담센터 |
|---|---|---|---|---|
| `remaining` | 잔여 처방 회기 | 잔여 이용 횟수 | 월 한도 잔여 | 잔여 회기 |
| `admission_type` | 입원·낮병동 | 당일 이용 중 | 인근 수급자 | 대기 내담자 |
| 보강 | 보강 치료 | 대체 프로그램 | 방문 재배정 | 상담 재배정 |

대기자 명단을 어떤 형태로든 관리하고 있다면 적용할 수 있습니다. 엑셀 한 장이면 충분합니다.

**치료 종목을 바꾸려면** `lib/mockData.ts`의 `THERAPIES` 배열만 교체하십시오.
복지관 프로그램, 방문요양, 상담 회기 등 예약 기반 서비스라면 같은 구조로 동작합니다.

### 매칭 규칙 변경

`lib/matcher.ts` 한 파일에 모여 있습니다.

**필수 조건 (AND)**
1. 대기 항목의 치료 종목이 빈 슬롯과 일치
2. 잔여 처방 > 0
3. 해당 시각에 다른 일정 없음

**우선순위 (순차)**
1. 잔여 처방 적은 순 — 소진 임박 우선
2. 대기 경과일 긴 순 — 편중 방지
3. `child_id` 오름차순 — 동점 해소, 재현성 보장

3단계 동점 처리 덕분에 같은 입력에는 항상 같은 결과가 나옵니다.

## 개인정보 처리

- 실제 환자 정보를 포함하지 않습니다
- 입력한 문자를 서버에 저장하지 않습니다 (로그 미기록)
- 브라우저 저장소를 사용하지 않습니다
- API 키는 서버 사이드에서만 사용합니다
- 업로드한 CSV는 브라우저 메모리에서만 처리되며 전송되지 않습니다

본선에서는 자체 호스팅 n8n과 로컬 언어모델(Ollama)로 옮겨, 원문이 기관 밖으로 나가지 않는 구조로 전환할 계획입니다.

## 알려진 한계

- 치료실·장비 정원은 배지로 표시만 하며 매칭 조건에 넣지 않았습니다. 결석으로 비는 자리는 이미 해당 치료실에 배정된 자리이기 때문입니다. 장비 준비 시간이 필요한 종목은 본선에서 별도 처리합니다
- 언어치료는 이번 범위에서 제외했습니다
- 하루 한 건의 결석만 처리합니다. 다건 동시 처리는 본선 범위입니다
- 로컬 모델의 한국어 추출 정확도는 아직 측정하지 않았습니다
