# 결정 기록 · Assumption Ledger (DECISIONS)

> 왜 이렇게 만들었는지의 기록. 같은 논의를 반복하지 않기 위한 문서다.

## 결정

### D-01. DB와 Auth를 쓰지 않는다

**맥락** — 기본 스택은 Supabase + Auth. 개발 가용 시간은 약 5시간.
**결정** — 데이터는 상수, 로그인 없음.
**근거** — 상태 저장이 불필요하고, 심사위원 즉시 접속이 요건이다. DB 도입은 개발 시간만 소모한다.
**대가** — 사용자별 이력 저장 불가. 예선 범위에서는 문제되지 않음.

### D-02. 매칭은 AI가 하지 않는다

**결정** — 종목 일치·잔여 기회·시간 충돌은 결정론적 규칙. AI는 언어 처리만.
**근거** — 재현성과 검증 가능성. "누가 먼저 치료받는가"를 AI가 정하는 구조는 윤리적 수용성이 낮다.
**부수 효과** — 화면에 AI/규칙 구간을 시각적으로 분리하면 이 주장이 증명된다. 시그니처 요소가 됐다.

### D-03. 우선순위는 형평 기준

**결정** — 잔여 기회 적은 순 → 대기 긴 순 → ID 순.
**근거** — 영리 도구라면 수익성이나 배정 용이성으로 정렬한다. 이 정렬 조건 한 줄이 비영리 도구임을 코드로 드러내는 지점이다.
**주의** — 성능 개선 목적으로도 이 순서를 바꾸지 않는다.

### D-04. 치료실 정원을 매칭 조건에 넣지 않는다

**결정** — 배지로 표시만.
**근거** — 결석으로 비는 자리는 이미 해당 치료실에 배정된 자리다. 같은 자리에 다른 대상자를 넣으면 정원이 변하지 않는다.
**미해결** — 수치료·로봇치료는 장비 준비 시간 때문에 즉시 대체가 어려울 수 있다. B1 참조.

### D-05. 폴백 파서를 일부러 단순하게 유지한다

**결정** — 정규식 파서가 부분 결석에서 실패하도록 둔다.
**근거** — 이 실패가 AI 필요성의 증거다. 개선하면 제품의 주장이 약해진다.
**부수 효과** — API 장애 시에도 화면이 죽지 않는 보험이 된다.

### D-06. 익명화를 파이프라인 앞단에 둔다

**맥락** — 로컬 모델의 한국어 정확도가 미검증이라 본선 실행 리스크가 컸다.
**결정** — 접수 직후 익명화, 발송 직전 재식별.
**근거** — 개인정보 경계가 모델 선택에서 분리된다. 로컬이 부족하면 모델을 바꿔도 경계가 유지된다.
**남는 위험** — 재식별. 희소 속성 조합으로 특정 가능. SPEC-PRIVACY.md 참조.

### D-07. 문제 진단을 두 번 수정했다

| 버전 | 진단 | 폐기 사유 |
|---|---|---|
| v1 | 정보 전달이 지연·누락된다 | 왜 그런지 설명 없음 |
| v2 | 결정권과 정보가 분리되어 있다 | **틀림.** 코디도 가용성을 조회할 수 있다 |
| **v3** | **접수 지점이 비결정적이고, 대조 비용이 처리 한계를 넘는다** | 현재 |

v3의 이점: "정보가 없다"는 반박 가능하지만("조회하면 되잖아요"), "대조 비용이 한계를 넘는다"는 산술로 증명된다.

### D-08. 언어치료를 범위에서 제외한다

**결정** — 물리치료·작업치료 8종만 다룬다.
**근거** — 1인 팀 4주. 범위를 좁힌 것이 오히려 실행 가능성의 근거가 된다.
**주의** — 실제로는 언어치료사 10명이 있다. 제출문에 "80명이 전부"라고 쓰지 않는다.

## Assumption Ledger

확정 전까지 사실로 취급하지 않는다.

### 확정

| # | 항목 |
|---|---|
| A1 | 물리치료사 40 · 작업치료사 40, 8종 치료, 30분 단위 |
| A2 | 코디네이터 2명 / 관리 아동 약 120명 |
| A3 | 결석 전날 10명 내외 · 당일 5명 내외 |
| A4 | 외래 아동 하루 평균 4건 |
| A5 | 대기 명단은 CSV로 조회 가능 |
| A6 | 결석 접수 지점은 코디·치료사 중 비결정적 |
| A7 | 입원·낮병동 대상자는 보강을 원한다 |
| A8 | 코디네이터는 배정 권한자이며 가용성 조회도 가능 |

### 미확인

| # | 항목 | 영향 | 확인 시점 |
|---|---|---|---|
| B1 | 수치료·로봇치료의 장비 준비 시간 제약 | 매칭 필수 조건 추가 필요 | 본선 1주 |
| B2 | 외래 평균 4건에 언어치료 포함 여부 | 범위 내 회기 수 변동 | 본선 1주 |
| B3 | 결석 공지 대상 범위 (전 직종 / 직종별) | 낭비 판단 수치의 분모 | 본선 1주 |
| B4 | 회수율 기준선 | **주지표의 기준값** | 본선 1주 |
| B5 | 로컬 모델 한국어 추출 정확도 | 모델 선택 | 본선 1~2주 |
| B6 | n8n 워크플로우 import 정합성 | typeVersion 조정 | 본선 착수 시 |
| B7 | 익명화 후 재식별 위험 수준 | 외부 모델 사용 가능성 | 본선 2주 |
| B8 | 오더코드 매핑표의 공개 가능 여부 | Apache 2.0 공개 범위 | 본선 전 |

**B4가 가장 중요하다.** 기준선 없이는 개선을 주장할 수 없다.
본선 1주차의 첫 산출물은 배정 기능이 아니라 이 계측이다.
