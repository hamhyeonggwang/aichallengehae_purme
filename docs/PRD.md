## 0. 한 줄

```
병원 코디네이터 2명이 결석으로 빈 회기를
대기 중인 재원 아동에게 연결할 수 있도록 돕는 "보강 브릿지"
```

**효용 단위 = 회기(session).** 시간 절감이나 오류 감소가 아니다.
회수된 치료 회기 1건이 가치 1단위이며, 모든 지표는 여기에 정렬한다.

**직접 사용자 = 코디네이터 2명.** 아동은 사용자가 아니라 수혜자다.
치료사 80명의 판단 부하 감소는 부수 효과다. 이 구분을 화면 설계 내내 유지한다.

## 1. MVP 경계 — 이 문서에서 가장 중요한 절

### 만드는 것 (단 하나의 흐름)

```
결석 문자 1건 입력
  → 무엇이 취소됐는지 추출
    → 비는 회기 확정
      → 회기별 보강 후보 제시
        → 안내문 초안 생성
```

### 만들지 않는 것 (Out — 명시적 폐기)

| 제외 | 이유 |
|---|---|
| 로그인 · 사용자 계정 | 심사위원 즉시 접속이 필수 요건 |
| 데이터베이스 | 상태 저장 불필요. 개발 시간만 소모 |
| 자동 발송(문자·알림톡) | 사전승인 리드타임 불확실 |
| 병원 시스템 연동 | 정보보안 심사 기간 확보 불가 |
| 다건 동시 처리 | 하루 1건 처리로 흐름 증명 충분 |
| 언어치료 | 이번 범위 제외 |
| 슬롯 간 후보 충돌 해소 | 슬롯 단위 그리디로 충분. 전역 최적은 본선 |
| 실제 Ollama 연동 | 공개 웹에서 시연 불가. n8n 파일로 대체 |
| 다크모드 · 애니메이션 · 통계 화면 | 심사 요건과 무관 |

> **Claude Code 지침**: 위 목록에 있는 기능을 "있으면 좋을 것 같아서" 추가하지 말 것.
> 범위 초과는 이 프로젝트에서 가장 큰 실패 요인이다.

## 2. 사용자

| 구분 | 대상 | 맥락 | 성공 조건 |
|---|---|---|---|
| **P1 직접 사용자** | 코디네이터 2명 | 결석 접수 직후, 다른 업무와 병행 중 | 입력부터 후보 확인까지 1분 이내 |

| **P3 심사위원** | 4인 | 첫 접속, 병원 맥락 모름, 체류 2~3분 | 설명 없이 예시 버튼 하나로 전체 체험 |

이 도구는 아동의 손상(Body Function)을 다루지 않는다.
**환경요인(e5800 일반 사회 서비스 체계 — 기관의 정보전달 구조)을 개선해
참여(Participation, 치료 프로그램 참여의 연속성)를 회복시키는 도구**다.

## 4. 기능 명세 — P0만

### F1. 결석 문자 입력

- textarea + 예시 3종 버튼(클릭 시 즉시 채우고 추출 실행)
- 예시는 난이도 상승 순으로 구성

| 단계 | 성격 | 문장 |
|---|---|---|
| 기본 | 전체 결석·대상 명시 | "아동 자 보호자입니다. 오늘 오후 치료 전체 못 갑니다." |
| 생략 | 시각·치료명 없음 | "애가 새벽부터 열이 나서 오늘 못 갈 것 같아요ㅠㅠ 다음주 화요일쯤은…" |
| **부분 결석** | **4건 중 2건만 취소** | "오늘 수치료랑 감통만 빼주세요. 물리치료랑 작업치료는 그대로 받을게요!" |

**수용 기준**
- [ ] 세 번째 예시에서 규칙 파서는 취소 대상을 특정하지 못하고 `확인 필요`로 비운다
- [ ] 같은 입력에서 AI 추출은 수치료·감각통합 2건만 지목한다
- [ ] 이 대비가 화면에서 관찰 가능하다 ← **AI 필요성의 시각적 증명**

### F2. 구조화 추출

- `POST /api/extract` → 카드 렌더
- 추출 필드: `subjectToken · date · scope · cancelledTherapies · reason`
- 신뢰도 < 0.7 → 노란 테두리 + "확신이 낮습니다"
- 추출 실패 필드는 **빈칸 유지**(환각 방지). 절대 추측값을 채우지 않는다
- 응답의 `source`가 `fallback`이면 화면에 "규칙 파서로 처리됨" 표시

**수용 기준**
- [ ] API 키가 없어도 화면이 동작한다
- [ ] 8초 초과 시 폴백으로 전환된다
- [ ] JSON 파싱 실패 시 폴백으로 전환된다

### F3. 대기 명단 CSV 업로드

- 기본값은 내장 상수, 업로드 시 교체
- 샘플 CSV 다운로드 버튼 제공
- 헤더 형식을 화면에 노출
- 파싱 실패 행은 건너뛰고 사유 표시

**수용 기준**
- [ ] 브라우저 메모리에서만 처리하고 서버로 전송하지 않는다
- [ ] 잘못된 행이 섞여도 나머지가 정상 처리된다

> **이 기능이 이식 논거의 핵심이다.** 심사위원이 "다른 기관이 쓸 수 있나"를 물으면
> 파일 교체를 그 자리에서 보여줄 수 있어야 한다.

### F4. 보강 후보 매칭

- 규칙 엔진으로 회기별 후보 최대 3건
- 각 후보에 근거 배지: `종목명` `잔여 N회` `입원/낮병동` `시각 가능`
- 순위 산정 근거를 한 줄로 표시
- 제외된 대기자와 사유를 접이식으로 노출

**수용 기준**
- [ ] AI를 호출하지 않는다
- [ ] 동일 입력에 항상 동일 순서가 나온다
- [ ] 화면에 "규칙이 정하는 구간" 표시가 있다

### F5. 안내문 생성

- 후보 선택 → 치료사용 안내문 + 복사 버튼
- "확정 아님 · 회신 후 배정" 문구 필수 포함

### F6. 안전 표시

- 상단 고정 배너: `가상 데이터로 동작합니다 · 실제 환자 정보는 포함되어 있지 않습니다`
- 하단 역할 분담표: 작업별 AI / 규칙 / 사람 구분

## 5. 데이터 계약

```ts
type Track = 'PT' | 'OT';

type TherapyCode =
  | 'PT_BASIC' | 'HYDRO' | 'ROBOT' | 'EQUIP'      // 물리치료 계열
  | 'OT_BASIC' | 'COG' | 'SI' | 'SWALLOW';        // 작업치료 계열

type Therapy = {
  code: TherapyCode;
  name: string;        // 물리치료 · 수치료 · 로봇치료 · 기구치료
  track: Track;        // 작업치료 · 전산화인지치료 · 감각통합치료 · 연하치료
  room: string;
  capacity: number;    // 표시 전용. 매칭 조건에 넣지 않는다(§6 참조)
  aliases: string[];   // 보호자 구어체 표현
};

type Therapist = {
  id: string;          // "PT-03"
  label: string;       // "물리치료사 3"
  track: Track;
  skills: TherapyCode[];  // 전원이 전 종목을 수행하지 않는다
};

/** 대기 1건 = 대상자 × 종목. CSV 한 줄에 대응 */
type WaitEntry = {
  childId: string;
  alias: string;              // 실명 금지
  admissionType: '입원' | '낮병동';
  therapy: TherapyCode;
  remaining: number;          // 잔여 기회 — 도메인 중립 개념
  waitingDays: number;
  busyTimes: string[];        // ["10:00", "14:00"]
};
```

### CSV 스키마 (이식 계약)

```csv
child_id,alias,admission_type,therapy,remaining,waiting_days,busy_times
C-01,아동 가,입원,HYDRO,1,19,10:00|14:00
```

`remaining`은 **잔여 기회**다. 재활병원에서는 잔여 처방 회기지만
복지관은 잔여 이용 횟수, 방문요양은 월 한도 잔여, 상담센터는 잔여 회기에 대응한다.
**필드명에 도메인 용어를 넣지 않는다.**

### 규모 상수

| 항목 | 값 |
|---|---|
| 치료사 | PT 40 · OT 40 = 80 |
| 치료 종목 | 8 |
| 코디네이터 | 2 |
| 관리 아동 | 약 120 |
| 결석 | 전날 10명 내외 · 당일 5명 내외 |
| 외래 아동 1인당 | 평균 4건 |

> 화면 표시는 가상 데이터 예시값이며 제출문 수치와 일치할 필요 없다.
> 배너로 가상 데이터임을 이미 고지한다.

## 6. 규칙 엔진 명세 — 정확히 이대로 구현

**필수 조건 (AND)**

1. 대기 항목의 `therapy`가 빈 회기의 종목과 일치
2. `remaining > 0`
3. 해당 시각이 `busyTimes`에 없음

**우선순위 (순차 적용)**

1. `remaining` 오름차순 — 소진 임박자 우선
2. `waitingDays` 내림차순 — 대기 편중 방지
3. `childId` 오름차순 — 동점 해소

> **3단계 tie-breaker는 필수다.** 동일 입력에 동일 출력이 나와야
> "AI가 아니라 규칙이 정한다"는 주장이 검증 가능해진다.

**치료실 정원(`capacity`)은 매칭 조건에 넣지 않는다.**
결석으로 비는 자리는 이미 해당 치료실에 배정된 자리이므로 정원이 변하지 않는다.
배지로 표시만 한다. 장비 준비 시간이 필요한 종목(수치료·로봇치료)은 본선 과제.

**우선순위 기준은 형평이다.** 수익성이나 배정 용이성으로 정렬하지 않는다.
이 한 줄이 영리 도구와의 차이를 코드로 드러내는 지점이므로 주석으로 명시할 것.

## 7. AI 명세

- 모델: `claude-sonnet-4-6` (환경변수 `ANTHROPIC_MODEL`로 교체 가능)
- 호출: **서버 라우트에서만.** 클라이언트 직접 호출 금지(키 노출)
- 출력: JSON only. 백틱·서문 금지

**프롬프트 규칙**

- 명시되지 않은 항목은 반드시 `null`. 추측 금지
- `scope`: 전체 결석 `"all"` / 일부 `"partial"`
- `cancelledTherapies`: `partial`일 때만. "A는 그대로 갑니다"는 제외 대상으로 처리
- `subjectToken`은 알려진 토큰 목록(`C-01`~`C-09`) 내에서만 반환 — 익명화 이후이므로 별칭·실명은 입력에 없다
- 각 필드에 0~1 신뢰도 부여

**폴백 (필수 구현)**

| 상황 | 동작 |
|---|---|
| API 키 없음 | 즉시 정규식 파서 |
| 타임아웃 8초 | 정규식 파서 |
| JSON 파싱 실패 | 정규식 파서 |
| 폴백도 실패 | 빈 카드 + "직접 지정해 주세요" |

> 폴백은 보험이자 **시연 장치**다. 규칙 파서가 부분 결석에서 실패하는 모습이
> AI 필요성의 증거가 된다. 일부러 단순하게 유지할 것.

## 11. 비기능 요구사항

### 개인정보 · 보안 (필수)

- 실제 환자 정보 미포함. 아동은 `아동 가~아` 별칭, 치료사는 `PT-01` 형식
- API 키는 서버 환경변수. 클라이언트 번들 포함 금지
- 사용자 입력을 서버에 저장하지 않음(로그 미기록)
- `localStorage` / `sessionStorage` 미사용
- 업로드 CSV는 브라우저 메모리에서만 처리
- 상단 배너로 가상 데이터 상시 고지

### 성능 · 접근성

- 첫 화면 로드 2초 이내
- AI 추출 5초 이내, 초과 시 폴백
- 명도 대비 WCAG AA
- 키보드 포커스 가시화
- `prefers-reduced-motion` 존중
- 모바일 세로에서 전체 흐름 사용 가능
