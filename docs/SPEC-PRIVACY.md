# 개인정보 처리 설계 (SPEC-PRIVACY)

> 이 문서는 데이터 경계의 정본이다. 개인정보 관련 코드를 수정하기 전에 반드시 확인한다.

---

## 원칙

**경계는 모델이 아니라 파이프라인 구조로 확보한다.**

모델에 원문을 그대로 보내면 개인정보 보호가 모델 선택에 종속된다.
로컬 모델의 성능이 부족해 교체하는 순간 경계가 무너진다.

익명화를 앞단에 두면 이 종속이 끊어진다.

| | 익명화 없음 | 익명화 있음 |
|---|---|---|
| 로컬 모델 | 안전 | 안전 |
| 외부 모델 | **위험** | 안전 |
| 모델 교체 | 재심사 필요 | 영향 없음 |

**모델 성능과 개인정보 보호가 독립적으로 결정된다.**

---

## 파이프라인에서 실명이 존재하는 구간

```
접수 ──[실명]──> 익명화 ──[토큰]──> 모델 추출
                              │
                            [토큰]
                              ▼
                          매칭 규칙
                              │
                            [토큰]
                              ▼
                          재식별 ──[실명]──> 승인 큐
```

**양 끝뿐이다.** 중간의 모델 추출과 매칭은 토큰만 다룬다.

---

## 익명화 처리 대상

| 종류 | 방식 | 신뢰도 |
|---|---|---|
| 대상자 성명 | 기관 명부 사전 대조 | 높음 |
| 휴대전화번호 | 정규식 | 높음 |
| 주민등록번호 | 정규식 | 높음 |
| 생년월일 | 정규식 | 중간 |
| 등록·차트번호 | 정규식 | 중간 |

매핑 테이블은 **해당 실행 컨텍스트 안에만 존재**하며 모델 호출 노드로 전달되지 않는다.
재식별 노드가 발송 직전에만 참조한다.

---

## 잔존 위험 — 재식별

익명화는 **직접 식별자만** 제거한다. 다음은 남는다.

> "어제 로봇치료 받다가 발작 있었던 아이인데요, 다음주 수술 때문에…"

이름이 없어도 **희소한 속성의 조합**이 식별자가 될 수 있다.
특히 로봇치료(정원 2)·연하치료(정원 2)처럼 대상자가 적은 종목은 위험이 크다.

### 완화 방향

- `reason` 필드를 자유서술이 아닌 **범주값**으로 제한 (`열` · `개인일정` · `기타`)
- 모델에 전달하는 텍스트 길이를 제한
- 진단명·처치명이 포함된 문장은 추출 대상에서 제외

이 완화는 본선 과제다. 예선 프로토타입은 가상 데이터만 다루므로 해당 없음.

## 데이터별 외부 전송 가능성

| 데이터 | 외부 API |
|---|---|
| 익명화된 결석 문자 (사유 범주화) | 가능성 높음 |
| 익명화된 결석 문자 (사유 자유서술) | 조건부 |
| 대기 명단 CSV | **불가** — 조합 자체가 준식별자 |
| 매칭 결과 | **불가** — 애초에 모델에 보내지 않음 |

현재 설계에서 **모델이 보는 것은 결석 문자 하나뿐**이다.
대기 명단과 매칭은 모델을 거치지 않으므로 검토 표면이 최소로 유지된다.

---

## 기본 구성

**기관 내부의 로컬 모델을 기본으로 한다.** 익명화 계층이 앞단에 있으므로
모델 교체가 개인정보 경계에 영향을 주지 않는다.

의료기관의 외부 클라우드 전송은 익명화 여부와 무관하게 **내부 심의 사안**이다.
기술적 안전성과 별개의 절차이므로, 배포 시점의 승인 결과에 따른다.

---

## 예선 프로토타입 (웹)

가상 데이터만 사용하므로 위 파이프라인을 구현하지 않는다. 대신 다음을 지킨다.

- 실제 환자 정보 미포함. 아동은 `아동 가~자`, 치료사는 `PT-01` 형식
- API 키는 서버 환경변수. 클라이언트 번들 포함 금지
- 사용자 입력을 서버에 저장하지 않음 (로그 미기록)
- `localStorage` / `sessionStorage` 미사용
- 업로드 CSV는 브라우저 메모리에서만 처리
- 상단 배너로 가상 데이터임을 상시 고지
