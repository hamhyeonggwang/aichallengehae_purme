# 범위 경계 (SPEC-SCOPE)

> 이 문서는 **범위 판단의 정본**이다. 기능 추가 요청이 오면 여기부터 확인한다.

---

## 만드는 것 — 단 하나의 흐름

```
결석 1건 접수
  → 무엇이 취소됐는지 추출
    → 비는 회기 확정
      → 회기별 보강 후보 제시
        → 안내문 초안 생성
          → 사람이 승인
```

이 흐름 하나를 끝까지 작동시키는 것이 목표다.
**흐름을 넓히지 말고 깊게 만든다.**

---

## 만들지 않는 것 (Out)

### 예선 프로토타입에서 제외

| 항목 | 이유 |
|---|---|
| 로그인 · 사용자 계정 | 심사위원 즉시 접속이 필수 요건 |
| 데이터베이스 | 상태 저장 불필요. 개발 시간만 소모 |
| 자동 발송 (문자·알림톡) | 사전승인 리드타임 불확실 |
| 병원 시스템 직접 연동 | 정보보안 심사 기간 확보 불가 |
| 다건 동시 처리 | 1건으로 흐름 증명 충분 |
| 슬롯 간 후보 충돌 해소 | 슬롯 단위 그리디로 충분 |
| 실제 Ollama 연동 | 공개 웹에서 시연 불가. n8n 파일로 대체 |
| 통계·대시보드 화면 | 심사 요건과 무관 |
| 다크모드 · 페이지 전환 애니메이션 | 심사 요건과 무관 |
| 다국어 | 해당 없음 |

### 영구 제외 (본선에서도 하지 않음)

| 항목 | 이유 |
|---|---|
| AI의 배정 우선순위 결정 | 윤리적 수용성. 제품의 핵심 주장에 반함 |
| AI의 자동 발송 (사람 승인 없이) | 책임 소재 불명확 |
| 수익성·배정 용이성 기준 정렬 | 형평 기준을 대체할 수 없음 |
| 실제 진료정보의 저장소 커밋 | C2 위반 |

### 본선 범위 (예선에서는 하지 않음)

- n8n 워크플로우 import 검증 및 현장 배치
- 로컬 모델(Ollama) 한국어 추출 정확도 측정
- 익명화 계층의 재식별 위험 평가
- 회수율 기준선 실측 (본선 1주차)
- 다건 동시 처리 · 전역 최적 배정
- 언어치료 종목 확장

## 판단 기준

새 기능 요청이 왔을 때 순서대로 확인한다.

1. **Out 목록에 있는가** → 구현하지 않고 이유를 밝힌다
2. **위 흐름의 어느 단계에 속하는가** → 속하지 않으면 범위 밖이다
3. **없으면 흐름이 끊기는가** → 끊기지 않으면 미룬다
4. **수용 기준(`docs/PRD.md`)에 해당 항목이 있는가** → 없으면 범위 밖이다

넷 중 하나라도 걸리면 **구현 전에 물어본다.**

## Exit — 손을 떼는 방법

이 프로젝트는 1인 팀이 만들며, 공개 후 유지보수 인력이 없을 수 있다.
그 조건에서도 다른 기관이 독립적으로 운용할 수 있어야 한다.

| 자산 | 이식 방법 |
|---|---|
| 매칭 규칙 | `lib/matcher.ts` 한 파일. 정렬 조건 한 줄 수정으로 우선순위 변경 |
| 데이터 계약 | `docs/SPEC-RULES.md`의 CSV 스키마. 필드명에 도메인 용어 없음 |
| 서비스 종목 | `lib/mockData.ts`의 `THERAPIES` 배열 교체 |
| 자동화 경로 | `n8n/workflow.json` import 후 3곳 수정 |

**개발자 없이 유지되도록 설계한다.** n8n 워크플로우는 화면에서 노드를 보며 수정할 수 있어,
코드를 다루지 않는 담당자도 운영할 수 있다.
